01 · Executive Summary

What ships, what degrades, what dies

The extension inherits Pomo's product soul — fractional-second live timing, terminal-density stats, snap transitions, cool monochrome with one signal red — and gains a new native surface: the New Tab page becomes the always-open instrument. Three Android capabilities do not survive the move unchanged.

FULL Timer · History · Stats · Notifications

The entire local-first feature set ports cleanly. IndexedDB replaces Room; the Kotlin state machine becomes a TypeScript engine; chrome.notifications replaces the Android notification channel.

DEGRADED Background resilience

MV3 service workers suspend after ~30s idle; alarms fire at 30s+ granularity. Timing survives via timestamp math (endAt + recompute), but the engine only advances while Chrome runs. The browser, not the OS, is the keeper of time.

REMOVED LAN server · Widget

Extensions cannot open listening sockets in MV3 — the LAN HTTP/WebSocket API needs a native-messaging host or a companion process. The home-screen widget maps to a toolbar badge instead.

North star Chrome becomes a second instrument: the New Tab page renders Pomo at full-screen density, the badge keeps a live countdown in the toolbar, and the engine stays a faithful port of the phone's state machine — Room schema, phase rules, midnight-crossing history, and streak logic ported 1:1.

03 · Platform Constraints

The four walls of Manifest V3

Everything in this plan bends around these four constraints. They are walls, not fences — each has a documented workaround.

WALL 1 Service worker lifecycle

A worker dies after ~30s of inactivity. No timers survive suspension. Workaround: never rely on wall-clock ticks. Persist endAt on every transition; on wake, recompute remaining. chrome.alarms (min period 30s) wakes the worker to reconcile state and refresh the badge.

WALL 2 No listening sockets

MV3 has no API to open a TCP/HTTP server (chrome.sockets is Chrome Apps territory, deprecated). The LAN desktop API cannot exist inside the extension. Workaround: optional native messaging host binary owns the server; the extension owns state and forwards commands through the host.

WALL 3 No long-lived WebSockets

Service workers are suspended regardless of open sockets; a WS connection is severed silently. Crew relays break. Workaround: HTTP polling at 60s cadence via alarms, or a keepalive ping every ~25s to hold the worker alive while the tab is open. Expect higher latency; expose SYNCING/stale states honestly.

WALL 4 Timed execution is best-effort

If Chrome is closed, nothing runs. No foreground service, no boot receiver. Workaround: accept the platform: on next browser start, reconcile against endAt — a session that "expired" while Chrome was closed completes as if it had finished on time.

Design consequence The phone remains the *source of truth* for anyone running both. The extension is a second, independent instrument — same engine, same schema, separate data. Cross-device sync stays a non-goal, consistent with PRODUCT.md.
04 · Architecture

Layered, storage-backed, UI-agnostic

Key migration decision

IndexedDB uses schema versioning (onupgradeneeded). Adopt the same version-number discipline as Room's migration chain so future schema changes are additive. The extension's data is not migrated from the phone — separate instrument, separate history, per PRODUCT.md's no-sync stance.

07 · UI Surfaces

Four surfaces, one instrument

All four render the same engine state. Design tokens come straight from PRODUCT.md: cool slate backgrounds, cream text, single signal-red accent, monospace numerals, snap transitions, no bounce.

1 New Tab — the instrument

Full-page Pomo: fractional-second readout, phase band, today's session count, streak, and a dense stats strip. One tap to start — no modal, no setup. This is the product's primary home and its best argument for existing.

2 Side panel — the companion

Docked on the workspace edge. Shows the live readout, quick start/pause/reset, and the three stats questions (total time, focus window, streak). Persists while Chrome runs.

3 Popup — the quick control

Compact card from the toolbar: phase, time, start/pause, reset, skip. Lower-30% one-handed rule becomes bottom-third rule. Two taps max to any control.

4 Badge — the countdown

Toolbar badge shows M:SS remaining, red during focus, muted otherwise. Refreshed by the 30s alarm loop; recomputed from endAt so it never drifts between ticks.

Design rules carried over

  • Data is the design — numbers largest on every surface; sub-second tick visible in New Tab.
  • Snap, don't bounce — phase transitions instant; no crossfades, no spring curves.
  • One signal color — red marks live state, peaks, urgency. Nothing warm, nothing gold.
  • Glanceable — time readable from across the room at full-screen sizes; AA contrast in both themes.
  • Empty/loading/error states — every surface defines all three, per PRODUCT.md.

10 · Risks & Mitigations

What will try to kill this

HIGH

Service worker suspension eats the timer

Worker killed during a focus session; state diverges from user expectation.

→ endAt-only timing; every wake reconciles. Browser-restart recovery path: complete expired sessions as-if-finished. Test this path explicitly.

HIGH

Crew relay staleness

Polling can't match WebSocket freshness; leaderboard feels dead, ranks go stale.

→ 60s poll + explicit SYNCING/age UI (already specced in PRODUCT.md). Extend relay API with conditional GET/ETag if the relay allows.

MED

Engine drift between phone and extension

Two implementations of the same rules; behavior diverges quietly.

→ One spec, one fixture set. Port the Android unit-test matrix to TS; golden files for phase schedules and ranking windows.

MED

Storage quotas & async DB races

IndexedDB writes from a waking worker can race with UI reads; quota edges on Crew cache.

→ Single-writer rule; versioned stores; cap crewCache rows (e.g. 30 days of snapshots).

LOW

New Tab override = risky default surface

Chrome flags some newtab overrides; users may not want a timer on every new tab.

→ Keep newtab as the flagship but make it skippable in settings (side panel becomes home).

LOW

Store review friction

Host permissions, native messaging host, or minimal_installation issues at CWS.

→ Start with zero host permissions; add bridge only via separate listing or opt-in unpacked path.

12 · Acceptance Criteria

Shipped looks like

  • 3-second start — a first-time user starts a focus session within 3 seconds of opening a new tab, no onboarding.
  • 1-second glance — phase, remaining time, and today's session count readable in one glance at desk distance.
  • Live readout — fractional seconds visibly tick in the New Tab surface.
  • Survives tab close — closing the New Tab never loses the session; badge keeps counting via the worker.
  • Browser-restart recovery — a session that elapsed while Chrome was closed completes and commits on next start.
  • Stats answers three questions — total focus time, focus window, streak, without scrolling.
  • Crew parity — ranking windows, ties, staleness, and recovery rules match the phone against the same fixture.
  • AA contrast — WCAG AA on all text in both themes, per PRODUCT.md.
  • Store-ready — privacy copy truthful: no accounts, relay data is self-reported aggregates only.
Decision needed before M4 Crew parity on the extension is the only feature whose cost is close to its value on a browser. Options: (a) full parity with polling transport, (b) read-only spectator mode for the member's own Crew, (c) skip Crew in v1. Recommend (a) if relays ship conditional polling; otherwise (b).
